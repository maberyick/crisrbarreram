MANTIS · retinal layer segmentation · design note

How a vision transformer sees an OCT B-scan

The model does not look at pixels. It looks at tiles — and on a macular B-scan one tile is about 62 µm deep, which is thicker than the retinal pigment epithelium, the ellipsoid zone and the external limiting membrane put together. Almost every design decision below follows from that one number.

MANTIS is this project's OCT model: the VisionFM retinal foundation-model backbone, given our continued pretraining on 3.2 million B-scans and our per-structure fine-tuning, with an OctMoE mixture-of-experts block and LoRA adapters on top. Everything below is about MANTIS — what it does today, and where the design should go next.

1 · vocabulary

A token is not a pixel. It is a tile.

You already have the right intuition from language models: text is chopped into tokens, and one token is roughly one short word — about four characters. The model never sees letters; it sees a sequence of tokens.

Vision transformers borrow the machinery wholesale. The only thing that changes is what gets chopped. An image is cut into a regular grid of squares, and each square becomes one token. The square is called a patch. It is the atom of the model: attention, memory cost and the decoder all operate at patch granularity, never below it.

MANTIS today resizes each B-scan to 512 × 512 and uses a 16 × 16 patch. That gives a 32 × 32 grid — 1,024 tokens per B-scan.

Each patch — 16 × 16 = 256 pixel values — is turned into a single list of 768 numbers. That list is the embedding: the model's internal description of that tile. Everything downstream works with those 1,024 vectors and nothing else.

2 · the honest version

“Patching destroys detail” is the wrong criticism.

It is tempting to say that squeezing 256 pixels into one token throws information away. Mathematically, it does not.

The patch embedding is a linear map from 256 numbers to 768 numbers — it goes up in dimension, not down. It is over-complete. There is more than enough room in the output to hold everything that was in the patch.

The real problem is subtler and it is about organisation, not capacity:

Two different claims

“the patch embedding loses detail”false
“nothing rewards keeping it”true

Both are about the same 16 × 16 square — but only the second one is a reason to change the design.

The precise statement

Sub-patch detail is not destroyed — it has to be carried inside a token vector and then decoded back out. Nothing in the self-supervised pretraining objective explicitly rewards the model for doing that well. So fine detail is not privileged. It survives only if it happens to be useful for whatever the pretraining task was.

3 · microns

One patch is thicker than three retinal layers.

Here is where the abstraction collides with the anatomy. These are measured values from our gold-standard set, not textbook figures.

Axial (depth) resolution is 3.9 µm per pixel; laterally it is about 5.7 µm. Total retinal thickness from the ILM (inner limiting membrane, the vitreous-facing surface) down to BM (Bruch's membrane, the outer boundary) averages 75.5 px = 294 µm, with a 95th percentile of 98.9 px.

The individual layers we are asked to trace are far thinner than that: ELM (external limiting membrane) is 1–2 px; EZ (ellipsoid zone) is 2–3 px; RPE (retinal pigment epithelium) is 2–4 px.

A single 16-pixel patch spans 62 µm of depth. The entire retina is only 4.7 patches thick. Several distinct layers routinely fall inside one token.

4 · the key idea

Buy resolution by not spending tokens on vitreous.

The obvious fix — use smaller patches everywhere — is unaffordable. Attention cost grows with the square of the token count, because every token attends to every other token. Halving the patch size in both directions quadruples the tokens and multiplies the cost by sixteen.

But look at where the tokens are currently going. On a 496-row B-scan the retina occupies only 76–99 rows — about 18% of the image. The rest is vitreous above and choroid/sclera below.

You cannot simply crop to 100 rows, because the retina's position moves between scans: the topmost ILM row ranges from 41 to 102, and the BM row from 233 to 366. A fixed crop wide enough to catch every case still needs 325 of 496 rows — 66%, barely a saving.

The unlock is flattening: a standard OCT preprocessing step that re-aligns every A-scan column so Bruch's membrane becomes a straight horizontal line. Once the retina no longer wanders, the crop collapses to about 128 rows.

The punchline

The last two rows deliver identical depth resolution — 15.6 µm per token, 18.9 tokens across the retina. One of them costs exactly what we pay today. The other costs 256 times more. Resolution is bought by not spending tokens on vitreous and choroid, never by brute force.

5 · geometry

Retinal layers are sheets, so patches shouldn’t be squares.

A square patch encodes an assumption: that the image changes at the same rate in both directions. On a macular B-scan that assumption is simply false.

Layers are near-horizontal sheets. Move down by three pixels and you have crossed from ellipsoid zone into RPE — a different tissue. Move sideways by three pixels and essentially nothing has changed. Information density is anisotropic, so the sampling should be too.

Hence 4 pixels axially × 16 laterally: fine where the structure changes fast, coarse where it doesn't. Same token count, four times the depth resolution.

The chosen patch

6 · output

Sub-pixel precision has to be built into the output, not the input.

Even at 15.6 µm per token we are roughly 8× coarser than the ~2 µm of boundary precision that actually matters clinically. No patch size fixes that. So change what the model is asked to produce.

The conventional approach predicts a mask: a one-pixel-wide painted line, from which a boundary is extracted afterwards. That extraction quantises the answer to the pixel grid before anything is measured — the error floor is baked in at ±½ pixel ≈ 2 µm, and in practice worse, because the stair-steps also corrupt local slope and curvature.

The alternative is regression: instead of classifying pixels, predict a number. For every column x of the B-scan, output a continuous decimal row position y(x) — “the ILM in this A-scan sits at row 132.43”. There is no grid to snap to. The output is sub-pixel by construction.

The precision gap

finest token depth on offer15.6 µm

gap≈ 8×

No patch size closes a gap this size. The output representation has to.

7 · the crux

Dice is a proxy, and for thin layers it is a bad one.

The Dice coefficient measures how much two pixel sets overlap: twice the shared pixels divided by the total pixels in both. It is the default metric in segmentation, and for a blob — a tumour, a cyst, a fluid pocket — it behaves sensibly.

For a structure one pixel wide it behaves pathologically, in both directions:

  • Shift a perfect one-pixel line down by 2 pixels and the overlap goes to nearly zero. Dice collapses toward 0 — while the boundary is 7.8 µm off, which is clinically almost right.
  • Predict a thick band that comfortably contains the true line and Dice looks respectable — while the edge you would actually measure from sits several microns away.

Dice rewards being roughly in the right region. Layer analysis needs the boundary to be in the right place. Those are different questions.

What we actually measured

validation F10.833
boundary error, MANTIS8.50 µm
boundary error, legacy system6.14 µm

The top two are training metrics. The bottom two are the clinical claim — and they disagree.

This is not hypothetical — it happened here

During training, the metrics looked strong. On the held-out clinical gold-standard set, measured in microns against expert boundaries, MANTIS was worse than the legacy system it was meant to replace.

Why this matters for the paper

Dice and boundary error are not two views of one quantity — they are different measurements that can move in opposite directions. Only microns are a clinical claim. Dice is a training convenience that happens to be differentiable.

8 · context

The pathology you care about often sits outside the crop.

Cropping tightly to the retina is what makes the token budget work. It is also, taken alone, clinically naive.

In vitreomacular traction, the posterior vitreous separates from the retina peripherally but remains adherent at the macula, and pulls on it. The diagnostic evidence — the taut hyaloid membrane, its insertion point, the angle of the pull — lives above the ILM, in exactly the band of vitreous a tight retinal crop discards. The same argument applies below Bruch's membrane, where choroidal thickness and structure carry their own signal.

So the design is two branches, not one crop: a fine, retina-focused branch that buys boundary precision, running alongside a coarse whole-image branch (patch 32) that keeps the vitreous, the choroid and the global geometry in view. Precision and context are different jobs; give each its own resolution.

Two branches, two jobs

fine branch input128 × 512
fine branch patch4 × 16
coarse branch inputwhole scan
coarse branch patch32

The crop is what makes precision affordable. The second branch is what stops the crop from being blind.

9 · capacity

Mixture of Experts: eight sub-specialists, two consulted per token.

Everything above is about what a token is. This section is about what happens to it inside the network — and it covers the one structural choice in MANTIS whose value we have not yet demonstrated.

Inside a transformer, each block does two things to every token: attention, which lets tokens look at each other, and then a feed-forward network — a small two-layer network applied to each token on its own, which is where most of the block's parameters and most of its computation live. In a standard block there is one such network and every token goes through it.

A Mixture-of-Experts block (MoE) replaces that single network with several parallel copies, called experts, plus a small scoring network called the router. The router reads each token, scores the experts, and sends the token through only the highest-scoring few. The block's total capacity goes up — there are now eight networks' worth of parameters to specialise — but no individual token pays for all eight.

The clinical analogy is unusually exact. One generalist seeing every patient in the building is the standard block. A clinic with eight sub-specialists and a triage nurse at the door, sending each patient to the two most relevant rooms, is the MoE block. The building holds far more expertise; each patient still only sits in two rooms.

Reading the configuration line by line

8 experts, top-2. Each token is passed through the two best-scoring experts and their outputs are combined. Capacity scales with 8; per-token cost scales with 2.

Hard routing. A token is either sent to an expert or it is not — there is no soft blend of all eight in fixed proportions. That is what makes the saving real rather than notional, and it is also what makes the router's decisions worth inspecting: they are discrete choices you could tabulate.

Expert rank 32. The experts are low-rank updates — rank 32, in the same LoRA style MANTIS uses elsewhere — rather than eight full-size copies of the feed-forward network. LoRA (low-rank adaptation) means training a small, narrow correction on top of frozen weights instead of rewriting them. This is what makes eight experts affordable at all: the block does not become eight times larger.

Router conditioned on task family. The router is told which kind of problem it is being asked about — layer for the retinal layer heads, fluid or material for the fluid and material heads — before it scores anything. The next section is about why that distinction was worth encoding.

Why there is an extra loss whose only job is keeping the experts busy

Routing has a well-known failure mode. Early in training one or two experts are, by luck, slightly better than the rest. The router sends more tokens to them, so they get more gradient, so they get better still, so the router sends them more. Within a few epochs the routing has collapsed: two experts do essentially all the work and the other six are never selected, never trained, and never worth their parameters. You are paying for eight and getting two.

The fix is a small extra term added to the training objective — the load-balance loss — which penalises uneven expert usage across a batch. It does not tell the router which expert to pick; it only pushes the overall distribution of picks toward even. In MANTIS it carries a weight of 0.01: deliberately small, because it is a housekeeping constraint, not the thing we are actually trying to learn.

10 · two problems

Layers and fluid are not two versions of one task. They are two tasks.

This is the reason the router is conditioned on a task family, and it is worth being blunt about, because the two problems look superficially alike — both are called "segmentation", both are scored with Dice, both run on the same B-scans — and they share almost nothing underneath.

Retinal layers — ILM, ONL, EZ, RPE, BM — are always there. Every column of every B-scan crosses all five, in that order, top to bottom. They are thin (1–4 pixels), continuous, near-horizontal sheets. Because the ordering is an anatomical fact rather than a statistical tendency, it is a constraint you can rely on: the EZ cannot appear above the ONL. And because each boundary crosses each column exactly once, the task is essentially one-dimensional — for every A-scan column, output one row position. There is no class-imbalance problem, and no question of presence or absence.

Fluid and material — SRF (subretinal fluid), IRF (intraretinal fluid), cystic IRF, SRM (subretinal material), sub-RPE fluid — behave in the opposite way on every one of those points. They are often completely absent: on many B-scans there is nothing to segment at all. Where present, they are irregular two-dimensional blobs of variable number, size and position, with no ordering constraint to lean on. The task is two-dimensional region detection and delineation, plus a prior question the layer task never has to ask — is there anything here? And it is severely class-imbalanced: the overwhelming majority of pixels, and often entire slices, are background.

Even the useful kind of expert specialisation differs. For layers you would want experts that specialise by pathology, device or retinal region — the same five sheets, seen under different conditions. For fluid you would want experts that specialise by lesion type and appearance, and you need the model to be able to answer "nothing here" without embarrassment.

This is not a taxonomy exercise — the split is already wired into the pipeline

Four places where the code itself has had to acknowledge that these are different problems:

CONSEQUENCE 1

Skeletonisation is gated behind a layer check.

Thinning a prediction to a one-pixel line and enforcing continuity along it is a sensible clean-up for a sheet. On a fluid blob it is meaningless — you would be thinning a cyst to a thread. The post-processing runs only when the structure type is a layer.

CONSEQUENCE 2

Empty-mask handling matters only for fluid.

Because most fluid slices are empty, empty masks have to be stratified across splits and protected during sampling, or the model learns from a distorted picture of how often lesions occur. For layers there are no empty masks, so none of that machinery applies.

CONSEQUENCE 3

Per-column argmax is valid for layers and invalid for fluid.

Taking the highest-scoring row in each column gives exactly one boundary per column — correct for a layer, which always has exactly one. Apply it to fluid and it cannot express absence: it returns a lesion pixel in every single column, hallucinating disease across the whole scan.

CONSEQUENCE 4

The fluid heads carry a domain shift the layer heads do not.

Every fluid head was trained on diabetic macular oedema data (the RUBY study) and then evaluated on age-related macular degeneration. Different disease, different fluid morphology, different distribution. The layer heads face no equivalent shift.

So does the Mixture of Experts actually help?

The argument above is a good argument. It is not evidence. Here is what we can and cannot currently claim.

The only on/off ablation we have is the OPL layer. With MoE, best validation Dice was 0.4905 over 82 epochs. Without MoE, 0.5000 over 83 epochs. MoE scored slightly lower.

Three caveats matter, and none of them rescue the result. It is one structure out of sixteen. The difference is 0.0095 — well inside the noise you would expect from two training runs. And both runs used the flawed per-B-scan validation split — slices were assigned to training or validation individually rather than by patient, so neighbouring slices of the same eye sat on both sides of the split. That is leakage, and it inflates both numbers; neither is a clean estimate of anything. It is the same class of problem as the training-metric-versus-microns gap in section 7: the number on the dashboard is not measuring what you want it to measure.

To be exact about what this does and does not say: it is not evidence that MoE hurts. It is evidence that we do not yet know whether it helps. A proper ablation — MoE on versus off, across structures, on the corrected patient-grouped split — is outstanding work, and until it is run, the routing architecture should be described in the paper as a design choice, not as a result.

Summary

The four things to remember

ONE

The model's smallest unit is a tile, not a pixel.

At 16 × 16 that tile is 62 µm deep — thicker than ELM, EZ and RPE combined. Detail below that scale is not destroyed, but nothing in training privileges it.

TWO

Resolution is a budgeting problem.

Flatten to Bruch's membrane, crop to 128 rows, use 4 × 16 patches: four times the depth resolution for the same 1,024 tokens. The brute-force route to the same resolution costs 256× more.

THREE

Dice is not a clinical measurement.

MANTIS's val Dice 0.585 and F1 0.833 coexisted with 8.50 µm boundary error against a legacy system's 6.14 µm. Regress the boundary directly and report microns.

FOUR

Layers and fluid are different tasks — and the routing that assumes so is unproven.

Layers are always present, ordered and 1-D; fluid is often absent, unordered and 2-D. MANTIS routes on that distinction with 8 experts, top-2. But the only ablation we have — OPL, 0.4905 with MoE against 0.5000 without, on a leaky split — measures nothing. Run it properly before claiming it.
